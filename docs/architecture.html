Design

Three compose projects. One shared network.

Agents speak streamable HTTP to MCPJungle. Testers speak DNS, LDAP, TACACS+, RADIUS, SMTP, and NFS at the published host ports. The appliances meet on mcplab-shared.

MCP clients  ──streamable HTTP──►  MCPJungle :8080/mcp
                                      │
                 ┌────────────────────┼────────────────────┐
                 │  compose mcplab    │                    │
                 │   labdns  labinfo  maildev  ratarmount  │
                 └──────────┬─────────┴─────────┬──────────┘
                            │                   │
                 compose labldap         compose labtacacs
                   control :8443            taclabd :49/:300
                   labldapd                 :1812/:1813 :8080

Permanence vs. wipe

Bootstrap YAML and scenario files are desired state. Anything an MCP tool mutates must come back with make reset or a *_state_reset tool. Gateway registration is tmpfs. The only durable host paths a profile may define are NFS_ARCHIVE_DIR and NFS_DATA_DIR.

Security model

Internal hops always use static bearer tokens on the isolated docker network. The single profile knob is LAB_DEV_MODE.

  • Hardened: enterprise gateway, redacted labinfo.
  • Dev: open gateway, revealed credentials staged world-readable under secrets/labinfo-creds/.
  • Phase 1 puts OAuth 2.1 / OIDC on a proxy in front of the gateway. The tools do not change.

Vendoring and pins

  • LabLDAP v0.2.2 — no local patch.
  • TacLab v1.3.0 — MCP pin relaxed with the upstream allow_legacy_clients knob.
  • LabDNS tracks default branch. patches/go-lab-dns-wire-mcp.patch wires Streamable HTTP into serve and relaxes the 2026-07-28 protocol pin so MCPJungle’s client can connect.
