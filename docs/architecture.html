Design

Three compose projects. One shared network.

Agents speak streamable HTTP to MCPJungle. Testers speak DNS, LDAP, TACACS+, RADIUS, SMTP, NFS, and the HTTP intercept proxy at the published host ports. The appliances meet on mcplab-shared.

Permanence vs. wipe

Bootstrap YAML and scenario files are desired state. Anything an MCP tool mutates must come back with make reset or a *_state_reset tool. Gateway registration is tmpfs. The only durable host paths a profile may define are NFS_ARCHIVE_DIR and NFS_DATA_DIR. After a YAML tweak, make reload APP=<app> recreates that one service; make up is first bring-up, a vendor pin bump, or a profile switch.

Security model

Internal hops always use static bearer tokens on the isolated docker network. The single profile knob is LAB_DEV_MODE.

  • Hardened: enterprise gateway, redacted labinfo, random-if-missing secrets. Leaving dev mode (marker secrets/.lab-dev-mode) unlinks and remints orchestrator tokens, runs LabLDAP setupsecrets --force and labgen -force, reloads running containers, and removes the marker last. LabLDAP TLS is not rotated (extra SANs are mode-independent; leaves may still be re-signed if LAB_PUBLIC_HOST is missing).
  • Dev: open gateway, revealed credentials staged world-readable under secrets/labinfo-creds/ (LDAP bind, RADIUS and TACACS+ shared secrets, TacLab lab-user passwords, LabLDAP CA PEM, optional TacLab client certs), and secret files reconciled from dev-credentials.yaml (including TacLab lab-user passwords and AAA shared secrets after labgen; fail-closed if missing; no merge with default; default profile ships lab-dev-* values, inert unless this knob is on). Catalog reconcile never inspects MCPJUNGLE_MODE. mcplab secrets reloads running containers whose files changed (or when the marker is missing / reloads is not done, or when LabLDAP leaves were re-signed for LAB_PUBLIC_HOST) and re-registers the gateway when registrar tokens change; make up skips those apps. The reloads=pending marker is written before catalog apply and setupsecrets/labgen, so a crash after those files land still retries. mcplab creds / make creds prints the same sheet from files on disk (fails closed outside dev; never prints TLS private keys). Dev-mode make smoke asserts those catalog values on the wire (Alice bind, RADIUS taclabAdmin, connections_list equal to disk). Default-profile smoke stays on random secrets and redaction.
  • Phase 1 puts OAuth 2.1 / OIDC on a proxy in front of the gateway. The tools do not change.

Vendoring and pins

  • LabDNS v1.1.1 — operator console on GET /. MCPJungle uses spec.management.mcp.allowLegacyClients: true in the profile YAML (no local patch).
  • LabLDAP v0.4.1 — native is the default engine; no local patch. Compose is compose.yaml + compose.ephemeral.yaml. Leaf certs include LAB_PUBLIC_HOST as a DNS or IP SAN in both modes; the lab CA private key is not committed.
  • TacLab v1.4.0 — MCP pin relaxed with the upstream allow_legacy_clients knob. Dev mode post-processes secret files after labgen; it does not patch the vendor.
  • LabMail v1.0.0-rc.3 — MCP pin relaxed with allowLegacyClients: true in labmail/bootstrap.yaml. Default originAllowlist: ["*"] for remote inbox JS. Compose service name stays maildev.
  • LabMITM v1.1.1 — MCP http://labmitm:8088/mcp. Compose must pass --management-listen=:8088. Unauthenticated data plane; intercept :443 only (CONNECT to LabLDAP/TacLab TLS is tunnel-not-decrypt). Exact Origins (no "*"). Token 0o644. No local patch.
  • ratarmount-rs v0.1.24 — NFSv3 export; NFSv4.1 is packaged but not enabled.
